# 11 — แผน +100 เท่า: จาก "รอคลิก" สู่ "ข้อมูลจริงหมุนเป็นความเร็ว"

หลัง docs/10 (ความเร็ว) — เจ้าของสั่งต่อ (2026-09-29): **ปลดคอขวด SQL แล้วปรับปรุงแผนให้ดีขึ้นอีก 100 เท่า**
แผนนี้ตอบสองคำถาม: (1) คอขวดถูกปลดได้จริงยังไงในวันนี้ (2) เมื่อปลดแล้ว อะไรทำให้ระบบเร็วขึ้น*อีก* 100 เท่า
โดยไม่หลอน (กติกาเหล็กข้อ 8 ยังครอบทุกไมล์สโตน)

## ส่วนที่ 1: คอขวดถูกปลดได้จริง — เปลี่ยนจาก "ปุ่มใน dashboard" เป็น "คำสั่งเดียว"

สิ่งกีดขวางเดิม: SQL 2 ไฟล์ต้องเปิด Supabase SQL Editor ด้วยมือ (เจ้าของกด 2 คลิก)
ทางแก้ (m37): **ปุ่ม Run ใน repo** — `node scripts/apply-migrations.mjs`

| ทรัพยากร | ความหมาย | เจ้าของต้องทำ |
|---|---|---|
| `SUPABASE_ACCESS_TOKEN` | กุญแจอนุญาตให้เครื่องเรา apply SQL แทนมือเจ้าของ (เส้นเดียวกับการอนุมัติที่ให้ไปแล้ว) | Supabase → Account → Access Tokens → สร้าง → วางใน **Settings → Environment** ของ Freebuff |
| `SUPABASE_DB` (ทางเลือก) | connection string ตรง (ตรวจลึกกว่า: RPC จริงตอบจริง) | Supabase → Project Settings → Database → Connection string |

เมื่อกุญแจอยู่ในระบบ: **คำสั่งเดียว** apply ทั้งสองไฟล์ + verify ทันที + รายงานผลจริง
(ไฟล์ออกแบบให้ re-runnable — รันซ้ำได้ ไม่มีทางเสียสองครั้ง) จากนั้น m17/m18/m19
(ครู AI เริ่มเรียนรู้จากนักเรียนจริง) เริ่มวิ่งทันที — นี่คือจุดที่ "เก่งขึ้น" กลายเป็นวงจรอัตโนมัติ

## ส่วนที่ 2: +100 เท่าหลังปลดคอขวด — สมมติฐานที่วัดได้

คอขวดที่แท้จริงถัดไปคือ **"เวลารอระหว่างข้อมูลจริงกับการปรับตัว"** — 100 เท่ามาจาก 4 ทาง (เรียงตามหลักฐาน):

| ทาง | กลไก | ตัวชี้วัด (กันหลอน = วัดจริงทุกรอบ) | ไมล์สโตน |
|---|---|---|---|
| **วงจรเรียนรู้สั้นลง** | ผลจริงรายสัปดาห์ → น้ำหนักกลยุทธ์ → แผนถัดไป **อัตโนมัติ** (จากแดชบอร์ดดูมือ → หมุนเอง) | เวลาจาก "นักเรียนซ้อมเสร็จ" → "ครูปรับวิธีสอน" < 24 ชม. | m38 |
| **ตอบจากของที่จำได้** | ขยาย answer cache (docs/10 m32) ให้ครอบคำถามยอดฮิตจากข้อมูลจริง (hot set) | hit rate คำถามยอดฮิต ≥ 60% · retrieval gate ≥80% คงเดิม | m34 + ข้อมูลจริง |
| **งานเล็กไม่ต่อคิวใหญ่** | routing สายสั้น: งานเล็กไปกฎ/โมเดลเล็ก งานใหญ่ค่อยโมเดลใหญ่ | latency p95 ลด ≥30% · eval suite ผ่านเท่าเดิม | m35 (คู่ m22) |
| **ไม่ห้อยรอของช้า** | budget ต่อ call — หมดเวลา = ตอบจาก KB/กฎที่ตรวจแล้วทันที | ไม่มีคำถามค้าง > budget ในทุกกรณี | m36 |

## ส่วนที่ 3: เส้นทางเดียวที่ "เร็วขึ้น" ได้โดยไม่หลอน

ทุกทางข้างบนแบ่งกลไกเดียวกัน: **เร็ว = ข้ามงานที่ตอบแล้ว/ไม่จำเป็น** ไม่ใช่ **ข้ามการตรวจ**
— การวัดทุกตัวในตารางจะถูกเพิ่มเป็นด่าน/บาร์ของ scorecard เมื่อถึงคิว (แบบเดียวกับด่าน 8)
ห้ามเคลมความเร็วที่วัดไม่ได้ — กติกาเดิมทุกข้อยังยืนอยู่
