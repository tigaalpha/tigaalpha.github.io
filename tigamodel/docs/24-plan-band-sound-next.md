### M8 · ทำแล้ว แต่ยังวัดไม่ได้ — และนั่นคือช่องว่างของเครื่องมือ

โค้ดใช้ `StereoPannerNode` แล้ว (เบส+กลองกลาง · ฉากซ้าย · สายขวา · ประสานกว้าง) และ
ถ้าเบราว์เซอร์ไม่มี node นี้จะ fallback เป็นมิกซ์เดิม — จึงไม่มีทางทำให้วงเสีย

**แต่ยังพิสูจน์ไม่ได้ว่ากว้างขึ้นจริง** เพราะ `scripts/band-audio-lab.mjs` เรนเดอร์โมโนช่องเดียว
ไม่มี `createStereoPanner` เลย ตัวเลขความกว้าง (L/R correlation, mono-compatibility)
จึงยังไม่มี — และเงื่อนไข mono-compatibility สำคัญมากสำหรับแอปที่คนฟังจาก
**ลำโพงเดียวของมือถือ** เสียงกว้างที่ยุบตอนรวมเป็นโมโนคือเสียงที่หายไปเงียบ ๆ

> **นี่คืองานที่ต้องทำต่อก่อนเชื่อว่า M8 ได้ผล** — ขั้นต่อไปของแผนคือทำให้แล็บเรนเดอร์สองช่อง

### M11 · ถอนแล้ว เพราะมันขัดกับ M12 ที่วัดได้จริง

ยก master จาก ×0.21 เป็น ×0.24 (+1.2 dB) แล้ววัดได้:

| | ก่อนยก | หลังยก |
|---|---|---|
| carol · median ของวงเทียบโน้ตผู้เล่น | −14.2 dB | **−13.5 dB** (เข้าเขตอันตราย) |
| classical · p90 | −12.9 dB | −12.1 dB |

**ยกวงขึ้น 1 dB = เข้าใกล้โน้ตผู้เล่นขึ้น 1 dB เป๊ะ** เพราะโน้ตผู้เล่นเล่นที่ระดับคงที่
ไม่ได้ถูกยกตาม ดังนั้นเป้า RMS −28…−24 dB ในแผนเดิม**เป็นไปไม่ได้จริง**
มันขัดกับเงื่อนไขที่สำคัญกว่า: ผู้เรียนต้องได้ยินตัวเองเล่น

→ คืนค่าเป็น ×0.21 และ**แก้เป้าในแผน** เป็น "ยกได้เท่าที่ M12 ยอม" ไม่ใช่ตัวเลขคงที่
→ ผลสุดท้าย: RMS **−34.2 … −35.9 dB** (เดิม −33.5 … −35.1) แทนที่จะเป็น −28…−24

### M9 · ไม่ผ่านเกณฑ์ — และรู้แล้วว่าทำไม

ขยับจาก 0.1–1.5 % เป็น **0.2–2.8 %** (เกือบสองเท่า · ศูนย์ถ่วงสเปกตรัมขยับจาก
109–164 Hz เป็น 125–190 Hz) แต่ยังห่างจากเกณฑ์ 4 %

สิ่งที่ลองแล้วและผล:

| วิธี | ผล |
|---|---|
| เปิด cutoff ของแผ่นเสียง 1500–2100 → 2400–3800 Hz | mid 6.4–18.1 → 9.1–25.1 % ✅ |
| ยกระดับแผ่นเสียงพร้อมกัน | ❌ ดันกลบเมโลดี้ (carol median → −15.5) จึงถอนระดับ คงไว้แค่การเปิดฟิลเตอร์ |
| ลดเบส 0.20 → 0.13 และเปิดฟิลเตอร์เบส 280 → 420 Hz | ช่วยทั้งสองทาง (เบสอยู่ใต้ 250 Hz จึงไม่กินโน้ตผู้เล่น) ✅ |
| ยกฉาก 0.10 → 0.16 | air ขยับเป็น 0.0–0.1 % เท่านั้น — ฉากอยู่ที่ 5–8 kHz ไม่ใช่ 800–2500 Hz |
| **ชั้นเสียงครึ่งหนึ่งคู่ (shimmer) ที่ 4× และ 6× ต้นนอง** | ✅ อันนี้ได้ผลจริง: upper 0.1–1.5 → 0.2–2.8 % |

**เหตุผลที่ทำได้แค่นี้:** เสียงทุกชิ้นคือออสซิเลเตอร์ตัวเดียวผ่าน lowpass ตัวเดียว
ฮาร์มอนิกของ saw ลดลงเป็น 1/n พอถึงฮาร์มอนิกที่แปดก็เหลือหนึ่งในสิบของต้นนอง
ฉากจริงมีนักดนตรีสายบนเล่นเอง ไม่ใช่ฮาร์มอนิกของสายล่าง — การใส่ชั้น 4×/6×
ทำให้คิดหน้าเหมือนนั้น แต่ที่ 4× ของ C4 คือ 1.0 kHz ซึ่ง**อยู่ในที่เดียวกับที่เมโลดี้อยู่**
การไล่ขึ้นไปอีกก็จะกินผู้เล่น ตามกติกาข้อ 5 ใน §24.4 จึง **หยุดที่ตรงนี้ ไม่ฝืนเกณฑ์**

## 24.5 บันทึกการถอน (1) · ตัวเลขระดับเสียงที่วัดผิด

`appBus()` เดิมเรียก convolver ดิบ ไม่ normalize — แต่ `ConvolverNode.normalize` default `true`
เบราว์เซอร์จึง normalize ให้เอง แล็บจึงบูมกว่าแอปจริงราว **+17…+18 dB** ทั้งชุด
→ ตัวเลข "ก่อน/หลัง" ที่วัดผ่านบัสทั้งหมดถูกยกเลิก รายละเอียดใน `23b` §11.7

## 24.6 บันทึกการถอน (2) · ตารางสเปกตรัมที่นับถั่วซ้ำ

`bandMix()` เดิมปัดทั้งสองปลายย่านเป็นบินแล้วอ่านแบบรวมปลาย (`k <= k1`)
→ **ถั่วที่ขอบถูกนับสองครั้ง** พิสูจน์ด้วยการวางพลังงานทั้งหมดที่ถั่ว 60 Hz:
sub 100.0 % + low 100.0 % = **200.0 %**

ผลกระทบ: คอลัมน์ `sub` ของแนวเบสหนักโด่งเป็น 38.3 % (จริง ๆ คือ 8.0 %)
→ **งาน "ลดเบสในย่าน sub" ถูกยกเลิก เพราะไม่มีปัญหานั้นจริง**

แก้เป็นช่วงครึ่งเปิด (`k1 = round(hi/hzPerBin) - 1`) ไล่ทดสอบขอบย่าน 9 จุด → ไม่มีย่านไหนซ้ำ
ตารางรวมได้ 98.7–99.7 % (ไม่ถึง 100 เป๊ะเพราะย่านครอบแค่ 20 Hz–14 kHz — เกณฑ์ที่ถูกคือ "ไม่เกิน 100 %")
