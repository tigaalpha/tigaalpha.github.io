## 3 · ปัญหาเชิงโครงสร้างที่ยืนยันได้จากโค้ด

### 3.1 หน้าให้คำแนะนำ 1 อย่าง ไม่ใช่คาบ
`recommendNext()` (`App.tsx:12201`) คืน **action เดียวเสมอ** จาก 6 ชนิด
ผู้เรียนจึงเจอคำถาม "แล้วต่อไปทำอะไร" ทุกครั้งที่เสร็จหนึ่งอย่าง
แผนที่ 4–5 ขั้นของ `TodayPage` มีอยู่แล้วแต่ไม่ถูกเรียกใช้

### 3.2 ไม่มี "ทำค้างไว้" — กลับมาแอปใหม่เท่ากับเริ่มใหม่
`page` ถูกกู้จาก `sessionStorage` (`App.tsx:11244`) และมี `replayLast()` ให้เล่นซ้ำล่าสุด
แต่**ไม่มี**ตัวเลขว่าเมื่อวานทำได้ถึงไหน / ค้างอะไร / ควรเริ่มตรงไหน

### 3.3 ฝึกจริงแล้วหน้านี้ไม่รู้ด้วยซ้ำ
`PRACTICE` เปิด `PracticeOverlay` (`App.tsx:13300`) เป็นหน้าเต็มจอ
ผลการฝึกอยู่ในนั้น ปิดแล้วกลับมาหน้านี้ = ไม่เหลือร่องรอยว่าเก่งขึ้นไหม

### 3.4 ทุกอย่างถูกวัด แต่ไม่มีอะไรถูกโชว์
`logActivity` / `recordMemory` / `recordNoteMisses` / `scoreDynamics` / `scoreRhythm` ทำงานครบ
แต่หน้านี้ไม่มีที่ไหนที่พูดว่า **"วันนี้คุณแม่นขึ้น 8% จากเมื่อวาน"**

## 5 · กติกาที่แผนนี้ต้องไม่ละเมิด

1. **ไม่แตะเศรษศาสตร์ที่จ่ายเงินจริง** — งานนี้ไม่เพิ่ม coins/gems เลย (เหมือนกติกาข้อ 4 ในแผน 25)
2. **ไม่สร้างเลขขึ้นเอง** — ทุกอย่างที่โชว์ต้องมาจากฟังก์ชันที่มีอยู่ (`TodayPage`, `getDueReviews`, `readActLog`, `recordNoteMisses`) ถ้าตัวไหนไม่มีข้อมูลจริง ให้ไม่แสดง อย่าเดา
3. **วัดก่อนเปลี่ยน** — หน้านี้กินเวลาเดียวกันกับ AI chat ซึ่งเป็นรายจ่าย AI ที่แพงที่สุดในแอป ต้องไม่เพิ่มการเรียก AI
4. **ห้ามทำให้เมโลดี้ผู้เล่นกลบเสียง** — หน้านี้คือที่เปิด practice drill ดังนั้นเกณฑ์ M12 จากแผน 24 ยังคุมอยู่
5. **โทรศัพท์เป็นแรงกดดันหลัก** — ของใหม่ทุกชิ้นต้องอ่านออกใน 1 ถ้ายังดีไม่ถ้าย

## 6 · สิ่งที่แผนนี้พิสูจน์ไม่ได้ (บอกไว้ตรง ๆ)

1. **"สนุกขึ้น" ผมวัดไม่ได้ด้วยตัวเลข** — P1–P7 คือการเอาสิ่งที่มีอยู่แล้วมายกขึ้นให้เห็น ไม่ใช่การพิสูจน์ว่ามันสนุกขึ้น
2. **ยังไม่ได้ดูข้อมูลการใช้งานจริง** — มี `logUsage("nav", …)` และตาราง `usage_events` อยู่แล้ว ควรดูก่อนว่าคนกดอะไรบนหน้านี้บ่อยสุด ก่อนสั่งงาน P3–P7
3. **ไม่รู้ว่าผู้เรียนส่วนใหญ่เข้าหน้านี้ตั้งแต่แรก** — หน้าเริ่มต้นจริงคือ `pathway` (`App.tsx:11244`) หน้านี้คือแท็บที่สาม ถ้าคนส่วนใหญ่ไม่ได้มาที่นี่ การปรับหน้านี้จะได้ผลน้อยกว่าที่คิด — **ต้องเช็กข้อนี้ก่อนลงมือ**
4. **ยังไม่ได้เปิดหน้านี้บนเครื่องจริง** — คอนเทนเนอร์นี้ไม่มี Playwright ทุกตัวเลขมาจากการอ่านโค้ด
5. **ยังไม่ commit งานนี้** — นี่คือแผน ยังไม่ได้แก้โค้ดหน้าไหน

## 8 · ผลการลงมืน (2026-10-03 · P1–P4)

เจ้าของสั่ง "ทำตามแผน" โดยยังไม่ได้ดูข้อมูล `usage_events` ข้อ 1–3 ในหัวข้อ 7
→ ทำ P1–P4 ที่ **ไม่ผูกกับคำถามนั้นเลย** เพราะทั้งสี่เป็นการย้ายของที่มีอยู่แล้ว
ไม่ใช่การเพิ่มของใหม่ ถ้าภายหลังพิสูจน์ว่าหน้านี้ไม่ใช่จุดที่คนยืนอยู่
ก็ยัง**ไม่ต้องรื้อ** — ย้าย `todaybar` ไป `pathway` ได้ในครั้งเดียว

### P1 — แผนวันนี้ขึ้นหน้านี้ ✅
`buildTodaySteps()` ถูกดึงออกจากใน `TodayPage` มาเป็นฟังก์ชันระดับโมดูล (`App.tsx:1159`)
และ `TodayPage` เรียกตัวเดียวกัน → **ตัวเลขสองหน้าตรงกันโดยโครงสร้าง ไม่ใช่โดยการเผื่อ**
ป้ายของแต่ละขั้นย้ายไป `TODAY_TAGS` ระดับโมดูลเช่นกัน บรรทัดเดียวกัน
หน้าเพิ่ม `todayPlan={{ total, done, pct, next }}` คำนวณด้วย `useMemo` ใน `PianoApp`
deps มีแค่ `lang`, `planTick`, `page === "sensei"` — ไม่อ่าน activity log ทุก render

### P2 — แถบเป้าหมายขึ้นบนสุด และเห็นตั้งแต่ streak = 0 ✅
`ChatProgress` ได้ prop `always` — ตรงนี้เรนเดอร์แม้ทุกอย่างเป็นศูนย์
ค่าเริ่มต้น (ไม่ใส่ `always`) ยังซ่อนเหมือนเดิมทุกที่อื่น จึงไม่กระทบที่อื่นในแอป
ย้ายออกจากใต้ช่องพิมพ์แชท (โมดัลแชทขยายยังเรียกตัวเดิม)

### P3 — ปุ่มเดียว "เริ่มคาบวันนี้" ✅
ปุ่มใน `todaybar` รัน `step.go()` ของ**ขั้นตอนแรกที่ยังไม่เสร็จ**
ขั้นตอนการบ้านไม่มี `go` ของตัวเอง → ปุ่มจะพาไปหน้าแผนเต็มแทน
**ไม่ทำ shortcut ติ๊ก "ทำแล้ว"** เพราะเป็นการสั่งให้ระบบเชื่อว่าทำโดยไม่ได้ทำ

### P4 — ฝึกจบแล้วหน้านี้เห็นความต่าง ⚠️ ทำได้ครึ่งเดียว
ส่วนที่ทำได้: `planTick` ถูก bump เมื่อ practice เปิด/จบ ทำให้ตัวเลขขั้นตอน "รีวิว"
อัปเดตทันที โดยยืนยันแล้วว่า `markPathAccuracy()` เขียน localStorage **ก่อน**
`setPracticeResult()` (`use-practice-mode.ts:799` ก่อน `:885`) จึงอ่านได้ค่าใหม่แน่นอน
ส่วนที่**ไม่ได้ทำ**: ข้อความ "ดีขึ้นตรงไหน" — ต้องมี before/after ที่ยังไม่มีบนหน้านี้
(ของที่มีคือ `teaching_outcomes` บนเซิร์ฟเวอร์ ซึ่งต้องรอถึง P6/P7)

### บั๊กที่เจอระหว่างทำ — และมันพังหน้าแอปจริง
`smoke-app-boot.mjs` จับได้: วาง `useEffect(... [practiceOpen, ...])` ไว้**ก่อน**
บรรทัดที่ destructure `practiceOpen` → `ReferenceError: Cannot access '…' before initialization`
ทุกครั้งที่แอปเรนเดอร์ (ErrorBoundary เต็มจอ) ยืนยันแล้วว่าเป็นของรอบนี้จริง
โดย build `HEAD` ใน worktree แยกแล้วรันสคริปต์เดิม → **ผ่าน 4/4** และหลังแก้ก็ผ่านอีก 4/4
แก้โดยย้ายบล็อกนั้นไปวาง**หลัง** `usePracticeMode(...)` พร้อมคอมเมนต์ห้ามย้ายขึ้น
