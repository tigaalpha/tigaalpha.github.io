### ที่ยังขาด (ตรงโจทย์ของเจ้าของ) ❌
1. **ไม่มีภาพ/กราฟในป๊อปอัป** — การ์ดเป็นข้อความล้วน
2. **ไม่มีชั้นความรู้** — บอกว่า "ควรฝึกอะไร" แต่ไม่**สอนว่าทำไม**
3. **ไม่มีชั้นความสนุก** — ไม่มีรางวัล/ควิซ/สตรีคผูกกับคำแนะนำ
4. **ไม่เรียนรู้จากผลจริง** — ตาราง outcomes ว่าง, policy ยังไม่ถูกปรับด้วยข้อมูล

## 4. ส่วนเสริมทั้ง 4 (รายละเอียดกลไก)

### 4.1 Knowledge Engine — เพิ่มความรู้
- **ตัวเลือกการ์ดความรู้:** ดึงจาก `tigamodel/knowledge` (KB + university-seed ที่มีแหล่งอ้างอิงจริง) กรองตาม (a) ระดับผู้เรียน (b) จุดอ่อนปัจจุบันจาก student model — **ความรู้ต้องอธิบายจุดอ่อนนั้น ไม่ใช่ความรู้ลอย ๆ**
- **โครงข้อมูล:** `{ id, concept_th/en/zh, why, visual, source_id, quiz{q,choices,answer}, badge_id? }` — เป็น data ล้วนในเครื่อง → **ไม่เสียค่า AI ต่อการแสดงความรู้**
- หมุนไม่ซ้ำใน 7 วัน, ครบ 3 ภาษา, ความยาวไม่เกิน 2 ประโยค

### 4.2 Fun Layer — ความสนุก
- **ควิซไมโคร:** 1 ข้อ/การ์ด จากการ์ดความรู้นั้น ตอบถูก +5 เพชร — **เติมเพชรต้องผ่าน RPC แบบ additive server-side ตาม hard rule ของ repo** (รูปแบบเดียวกับระบบเพชรเดิม ห้ามเขียน client ตั้งค่าตรง)
- **สตรีคความรู้** (แยกจากสตรีคซ้อม) + ป้ายถัดไปอีกกี่วัน
- **Knowledge Badges 8 อันแรก:** จอมจังหวะ · นักทฤษฎี · นักฟัง · มือขวามั่นคง · นักอ่านโน้ต · นักจังหวะช้า · นักเล่นอ่อนโยน · นักเล่นเป็นระบบ — ใช้ระบบ badge/เซเลอเบรชันเดิม (`badgeUp`)
- **เซอร์ไพรส์ ~10%:** fun fact วันเกิดคอมโพเซอร์ / คำท้า 7 วิ / ภาพเปรียบเทียบก่อน-หลัง
- คำชมแบบมีหลักฐานเสมอ: "แม่นขึ้น 16% จากเมื่อวันจันทร์" ห้ามชมลอย ๆ

### 4.3 Visual Engine — ภาพ/กราฟ
- Component เดียว `TeachVisual({ type, data })` → SVG inline ธีมตามแอป (`--text`, `--card` ฯลฯ) — ไม่เพิ่ม dependency
- 5 ประเภทเปิดตัว (เลือกจากข้อมูลที่มีจริง ไม่เดา):
  1. `mini-keyboard` — คีย์ย่อไฮไลต์โน้ตที่พลาด (มีข้อมูลจาก practice อยู่แล้ว)
  2. `accuracy-bars` — แท่ง 7 วัน + ตัวเลขล่าสุด
  3. `donut-progress` — % ความคืบหน้าบทเรียน/ระดับ
  4. `before-after` — เทียบสองช่วง (เช่น 7 วันก่อน vs วันนี้)
  5. `rhythm-grid` — จุดตกจังหวะตำแหน่งไหน
- fallback: ไม่มีข้อมูลพอ → ซ่อนภาพ ไม่โชว์กราฟว่าง

### 4.4 Intelligence Wiring — ต่อ tigamodel (ของที่วางไว้ Phase 0)
- `generateCoachTip` เดินผ่าน **tigamodel teaching-loop**: policy เลือกกลยุทธ์ → KB ประกอบความรู้ → โมเดล (ผ่าน router ที่สลับได้จากหลังบ้าน) เขียนข้อความ
- จบการซ้อมถัดไป: เขียนแถวลง **`teaching_outcomes`** (strategy_id, performance_before/after, outcome) — ตารางพร้อมใช้แล้ว
- หลังบ้าน: การ์ด "กลยุทธ์ไหนชนะ" จาก `admin_strategy_effectiveness` + แท็บใหม่ใน Model Lab: **Auto-Teach Preview** (ทดลองยิงป๊อปอัปกับ profile จริงโดยไม่ส่งผลผู้ใช้ทั่วไป)

## 5. แผนแบ่งเฟส

| เฟส | ส่งมอบ | คุณค่าที่ผู้เรียนรู้สึก | ขนาดงาน |
|---|---|---|---|
| **A — Popup 2.0** | TeachVisual 5 แบบ + การ์ดความรู้ (data ในเครื่อง) + ปุ่มควิซ (ยังไม่มีรางวัล) | "เห็นภาพ เข้าใจง่ายขึ้นทันที" | M (~1 วันทำงาน) |
| **B — Fun ครบ** | ควิซ + เพชร (RPC additive) + สตรีคความรู้ + badges 8 อัน | "สนุก อยากเจอครูอีก" | M |
| **C — ฉลาดขึ้น** | ต่อ teaching-loop + เขียน teaching_outcomes จริง + หลังบ้านกลยุทธ์ไหนชนะ + Auto-Teach Preview | "ครูปรับวิธีสอนตามผลจริง" | M-L |
| **D — เสียง & A/B** | เสียงบรรยายการ์ด (TTS เดิม), A/B เทียบโมเดลผ่าน router, รายงานผู้ปกครองแบบภาพ | ระยะยาว | L |

**เหตุผลลำดับ:** A ให้คุณค่ามองเห็นได้เร็วสุดและเป็นฐานของ B — C ต้องมี A/B ก่อนถึงจะมีข้อมูลเก็บ — D ใช้ของทุกชั้นที่วางไว้

| ตัวชี้วัด | เก็บผ่าน | เป้าหมายเริ่มต้น |
|---|---|---|
| % การ์ดที่กด "ลองเลย" | `logUsage("atip","try")` (มี "show" อยู่แล้ว) | +30% จากเดิม |
| ควิซ: เล่น/วัน + ความถูกต้อง | `logUsage("atip","quiz")` | ≥40% ของการ์ด |
| สตรีคความรู้เฉลี่ย | student model | ≥3 วัน |
| กลยุทธ์ไหนได้ผล | `teaching_outcomes` + RPC | มีข้อมูล ≥100 แถว/สัปดาห์ |

## 7. ข้อจำกัด & ความเสี่ยง (โปร่งใสตั้งแต่แผน)

1. **Bundle เดียวทั้งแอป** — TeachVisual เป็น SVG ล้วนไม่กี่ KB; ถ้าหนักจะ lazy-load (มีแพตเทิร์น dynamic chunk อยู่แล้ว)
2. **ต้นทุน AI** — ความรู้เป็น data ในเครื่อง (ไม่ยิง AI), ข้อความใช้ cache เดิม, โมเดลเลือกผ่าน router (มีรุ่นฟรี)
3. **ความถี่/สปาม** — คง priority guard เดิม + cap ไม่เกิน 2 การ์ด/วัน, ไม่ยิงกลางเพลง
4. **เศรษฐกิจเพชร** — เติมผ่าน RPC additive ที่ gate server-side เท่านั้น (hard rule)
5. **3 ภาษา** ครบทุกสตริงใหม่ (th/en/zh)

## 8. สิ่งที่จะไม่ทำ (ขอบเขตชัด)
- ไม่ใช้รูปภาพจากอินเทอร์เน็ต (ลิขสิทธิ์) — ทุกภาพสร้างเป็น SVG ในเครื่อง
- ไม่แตะระบบ payment/plan ที่มีอยู่
- ไม่สร้าง foundation model ใหม่ — ใช้ router + โมเดลที่ตั้งไว้ในหลังบ้าน
- ไม่ยิงป๊อปอัปให้ผู้ใช้ free (คง gating premium เดิม) จนกว่าจะมีข้อมูลว่าคุ้ม
