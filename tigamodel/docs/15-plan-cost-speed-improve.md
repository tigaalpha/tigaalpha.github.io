# 15 — แผนปรับปรุง: **ต้นทุนถูกลง + เร็วขึ้น + แผนดีขึ้น** (ต่อยอด docs/14)

คำสั่งเจ้าของ (2026-09-30): *ปรับปรุงแผนให้ดีขึ้นกว่าเดิม และเพิ่มความเร็วในการใช้งานโมเดล
ให้ดีขึ้น เร็วขึ้น และทำให้ต้นทุนการประมวลผลถูกลงอีก*

กติกาเดิมยังเป็นกติกา (กติกาเหล็ก 2/5/8): คุณภาพต้องผ่าน eval เท่าเดิมเสมอ, ทุกกลไก
ปิดได้ใน 1 นาที, ห้ามแลกความถูกต้องด้วยความเร็วหรือต้นทุน

## ส่วนที่ 1: แผนดีขึ้นอย่างไร — รวมสองเลนเป็นตัวชี้วัดเดียว

docs/10–14 ไล่มาคุยกันสองภาษา: "เร็วขึ้น" (latency) กับ "เก่งขึ้น" (คุณภาพคำตอบ) แต่ทั้งสองเลน
ระบายต้นทุนผ่านประตูเดียวกันคือ **จำนวน provider call ที่จ่ายจริงต่อหนึ่งคำตอบ** — แผนนี้จึงรวม
เป็นตัวชี้วัดเดียวที่วัดได้:

> **ต้นทุนต่อคำตอบที่มีคุณภาพ = (weighted units ที่จ่ายจริง) ÷ (คำตอบที่ผ่านเกณฑ์คุณภาพ)**
> ลดตัวเศษด้วย: ไม่ call ที่ไม่ต้อง call (governor) · ไม่คิดซ้ำสิ่งที่รู้แล้ว (answer cache,
> KB hot path) · เลือกเส้นทางถูกขนาดงาน (routing สายสั้น)
> ห้ามเล่นกับตัวหาร: "คำตอบที่มีคุณภาพ" คือคำตอบที่ eval/retrieval/policy ยอมรับเสมอ

| เลน | กลไกที่มีอยู่แล้ว | ผลที่วัดแล้ว | สถานะ |
|---|---|---|---|
| ลดความคิดซ้ำ | answer cache (m32) | hit < 1ms (scorecard ด่าน 8) | code รอสวิตช์ |
| ลดของเสียในบริบท | KB hot path (m34) | บล็อกแย่สุด 1.38MB → ≤8KB, เร็วขึ้น ~139× | **done (docs/14)** |
| **ลดการ call ที่ไม่จำเป็น** | **cost governor (m13/m22)** | **decide ก่อน call ทุกครั้ง; throttle ก่อนเพดาน 100% เสมอ; ปิด = เดิม 100%** | **ส่งมอบรอบนี้** |
| เลือกเส้นทางถูกขนาดงาน | routing สายสั้น (m35) | — | planned (คิวถัดไป) |
| ขอบเขตเวลาต่อ call | budget/timeout (m36) | — | planned |

## ส่วนที่ 2: ชิ้นจริงของรอบนี้ — Cost Governor (m13/m22 ส่งมอบ)

`cost-governor.js` + wiring `chatThroughCostGovernor` ใน web.js — สมุดบัญชีต่อเซสชัน
หน่วยถ่วงน้ำหนักจาก **cost tier ที่ provider ประกาศเอง** (free=0, low=1, medium=2, high=4):

| กติกา (docs/05 §8) | สิ่งที่โค้ดบังคับ | พิสูจน์โดย |
|---|---|---|
| เซสชันฟรี 40 คำถาม | freeQuota=40 หน่วยถ่วงน้ำหนัก; warn ครั้งเดียวที่ 80% (call ที่ 33 เมื่อจ่ายหน่วยเดียวต่อ call) | smoke 3 |
| throttle ก่อนเพดาน 100% | call ที่จะทำให้ spent+units > hardCap ถูกหยุด**ก่อน**เกิด; ที่ cap แล้วหยุดตลอด | smoke 3 |
| คุณภาพเป็นเงื่อนไขร่วม | คำตอบ throttle เป็น `status:"uncertain"` provider "cost-governor" — **ไม่แต่งคำตอบ**; สมองกฎ (policy/KB/แบบฝึกหัด) ยังตอบได้ไม่ง้อ provider; smoke/eval ทั้งชุดต้องเขียวใน merge เดียวกัน | smoke 5/7 |
| ตัวเลขจากของจริง | หลัง call ที่อนุญาต บันทึกหน่วยจริงจาก `declare().cost` ของ provider ที่ตอบ — mock (free) จ่าย 0; 100 call ฟรี = 0 หน่วย | smoke 7 |
| kill switch 1 นาที | `tiga_cost_governor` default OFF ในโมดูล; ปิด = decide allow ทั้งหมด + ล้าง ledger + เส้นทางเดิม byte-identical | smoke 2/7/8 |
| ห้าม bypass เพดาน | หน่วยเสีย/ติดลบ = 0; charge คลแมปที่ cap เสมอ (ขอ 999 ได้ 1) | smoke 4 |
| deterministic + bounded | ไม่มีนาฬิกา/สุ่ม; ledger LRU 500 เซสชัน | smoke 6 |

## ส่วนที่ 3: ตัวเลขเป้าหมายของแผน (วัดได้ ไม่ใช่ความรู้สึก)

| ตัวชี้วัด | ฐานปัจจุบัน (วัดจริง) | เป้ารอบนี้ |
|---|---|---|
| Provider call ที่จ่ายจริง/เซสชันฟรี | ไม่มีขอบเขต | ≤ 40 หน่วยถ่วงน้ำหนัก (เพดาน 100, warn ที่ 32) — **โค้ดบังคับ ไม่ใช่นิสัย** |
| ต้นทุน call ฟรี | 0 | 0 (cheap stays cheap — governor ไม่เวที provider ฟรี) |
| คำตอบที่ห้อย/แต่งหลัง throttle | — | 0 (uncertain + ที่มาเสมอ) |
| เวลา KB context เส้นทางแย่สุด | 0.041ms (m34 แล้ว) | คงไว้ (scorecard ด่าน 9 บังคับ) |
| Eval suite / retrieval gate | 93.1% / 100% | **เท่าเดิมหรือดีขึ้นเท่านั้น** (เงื่อนไขร่วม) |

## ส่วนที่ 4: คิวถัดไปของเลนต้นทุน-ความเร็ว

1. **m35 routing สายสั้น** — งานเล็ก (คำถามสั้น/งานจัดรูป) ไม่เข้าคิวโมเดลใหญ่; ตัดสินจาก
   declared latency+cost ของ router เดิม; เงื่อนไขร่วม eval เท่าเดิม
2. **m36 budget/timeout ต่อ provider call** — ช้าเกิน budget = ตอบด้วยกฎ/KB ที่ตรวจแล้ว
   (มีที่มา) ไม่ห้อย — ต่อยอด governedResponse เป็นรูปเดียวกัน
3. **m36b สะพาน governor → routing** — เมื่อเซสชันเข้าโซน warn ให้ router เอนไปทาง
   ผู้ให้ถูก (prefer_cost free-first) อัตโนมัติ แทนการ throttle ห้วน
4. **m44/m45/m46 (docs/14)** — คิวเดิม: สวิตช์ app_settings, hot counts ข้ามเซสชัน,
   eval capped-vs-legacy — ยังเป็นคิว ไม่ถูกแทนที่

> สรุปเลนคิดของรอบนี้: **"ถูกลงโดยไม่ถามโมเดลซ้ำ ไม่เทบริบททิ้ง และไม่ call เกินเพดาน"** —
> ทั้งสามประตูยังมี eval suite ยืนด่านเสมอ และทุกประตูปิดได้ใน 1 นาที
