# 12 — แผนพันเท่ารอบใหม่: กฎของวงจรทวีคูณ (compound loops)

เขียน 2026-09-29 หลังคอขวดถูกปลดจริง (m05 done — Learning Data รับข้อมูลจริงแล้ว,
policy-weights SQL applied เป็น seed-off) — รอบแผน "พันเท่า" นี้ต่างจากครั้งก่อน (docs/06):
**ตอนนั้นวางราก ตอนนี้รากมีของจริงให้รดน้ำ** ทุกไมล์สโตนจึงผูกกับข้อมูลจริงและวงจรที่หมุนซ้ำได้

> สูตรของรอบนี้: **พันเท่า = (1 + กำไรต่อรอบ)^จำนวนรอบ** — ไม่ใช่ก้าวเดียวใหญ่
> แต่ละวงจรด้านล่างต้อง "ปิดรอบได้เอง" (ผลของรอบกลายเป็นทุนของรอบถัดไป) และวัดผลได้ทุกรอบ

## ส่วนที่ 1: สามวงจรทวีคูณ (เรียงตามลำดับการปลดล็อก)

### วงจร A: แผนเฉพาะบุคคล (ปลดล็อกแล้ว — เริ่มวันนี้)

**สิ่งที่ขาดอยู่ตัวเดียว: สายไฟ** — client ยังไม่มีฟังก์ชัน "อ่าน" skill state กลับมา

| ทุกซ้อม 1 ครั้ง | ทุกคนได้หน้าเดียวกัน | แผนโน้มไปทางทักษะที่คนนั้นอ่อนจริง |

### วงจร B: ครูเรียนรู้จากผลจริง (ต้องรอข้อมูล ≥50 outcomes)

SQL พร้อม (m06) · เครื่องวิเคราะห์พร้อม (m04) · **ตัวนับเวลาคือ 50 ผลจริงแรก** —
งานของรอบนี้คือ m40: ตัวนับ + รายงานอัตโนมัติ เมื่อครบเกณฑ์ admin เห็นทันทีว่าเปิดสวิตช์ได้

### วงจร C: คลังความรู้โตจากปัญหาจริง (ต้องรอวงจร A+B ไหล)

m10/m19 เดิม — เมื่อ A ให้ข้อมูล "ใครติดตรงไหน" และ B บอก "สอนยังไงแล้ว work" —
KB wave ใหม่จะถูกเลือกจากปัญหาจริง ไม่ใช่การเดา (ผ่าน retrieval gate เสมอ)

## ส่วนที่ 3: เพราะอะไรจึง "พันเท่า" ได้

พันเท่ามาจากการ**คูณต่อ**ไม่ใช่บวกต่อ:
แผนเฉพาะคน (A) ทำให้เด็กอยู่ต่อ → ข้อมูลเพิ่ม → ครูเก่งขึ้น (B) → สอนดีขึ้น →
ปัญหาจริงชัด → คลังความรู้แม่นขึ้น (C) → สอนดีขึ้นอีก → วนกลับ A
**แต่ละรอบเต็มทำให้รอบถัดไปเริ่มจากจุดที่สูงขึ้นเสมอ** — นี่คือเหตุผลที่แผนรอบนี้
ใช้เวลาไปกับ "ปิดรอบ" (สายไฟ/ตัวนับ/แดชบอร์ด) มากกว่า "ความฉลาดใหม่"
— วงจรที่ปิดไม่ได้ = ทวีคูณไม่ได้ ไม่ว่าสมองจะดีแค่ไหน
