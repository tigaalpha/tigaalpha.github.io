# 08 — แผนสิบล้านเท่า: จาก "ครูที่เรียนรู้" สู่ "ครูที่โลกต้องมาเรียนวิธีสร้าง"

ต่อจาก docs/05 (ร้อยเท่า = วัดได้) และ docs/06 (พันเท่า = แผนบังคับตัวเอง) —
ฉบับนี้คือ **สิบล้านเท่า**: การเพิ่มจำนวนเด็กที่โมเดลช่วยได้ *คูณ* คุณภาพต่อเด็ก
*คูณ* ความเร็วที่โมเดลเก่งขึ้นต่อวัน — พร้อมกัน

## ส่วนที่ 1: ทำไม "สิบล้านเท่า" ต้องเปลี่ยนคำถาม

ร้อยเท่า/พันเท่า ถามว่า "ทำโมเดลที่มีให้ดีขึ้นยังไง" — สิบล้านเท่าถามว่า
**"จะทำให้ครูคนนี้สอนได้ไม่จำกัดจำนวนเด็ก โดยแต่ละคนได้ประสบการณ์ที่เหมือนครูส่วนตัว
และยิ่งสอนยิ่งเก่งขึ้นเอง โดยไม่เคยทำผิดกฎหมาย"** — คำตอบไม่ใช่ฟีเจอร์ แต่เป็น *4 ระลอกยุทธศาสตร์*

## ระลอก 1: ผู้เชี่ยวชาญเสมือน (Virtual Specialist) — เก่งขึ้นต่อเด็ก ×10

ทุกเด็กได้ครูที่ "เชี่ยวชาญตัวเขาเฉพาะ" — ไม่ใช่ครูดีคนหนึ่ง แต่ครูที่รู้จักเขาที่สุดในโลก

| งาน | อะไรที่เปลี่ยน | ปลดล็อกเมื่อ |
|---|---|---|
| **ครูที่จำได้ทุกอย่าง** (Learning Data) | ประวัติ จุดอ่อน ความชอบ อารมณ์วันซ้อม — ครูอ่านออกทุกครั้งก่อนพูด | SQL apply (อนุมัติแล้ว) |
| **แผนส่วนตัวที่ขยับตามจริง** (§3) | แผนไม่ใช่ตาราง แต่เป็นสิ่งมีชีวิตที่ปรับตามผลของ "เมื่อวาน" | Learning Data |
| **มือที่ 2 ที่ดูเห็น** (Multimodal §7) | กล้อง+ไมค์+การกดคีย์ → ครูเห็นสิ่งที่เด็กพูดไม่เป็นคำ | พร้อมเริ่ม |
| **เสียงสนทนาเรียลไทม์** (§10) | เด็กพูดขัดครูได้เหมือนครูนั่งข้าง ๆ | device จริง |

## ระลอก 2: ครูที่โตเอง (Self-Improving Teacher) — เก่งขึ้นต่อวัน ×10

วงจรที่ทำให้ "วันนี้ดีกว่าเมื่อวาน" เป็นเรื่องอัตโนมัติ:

| งาน | กลไก | สถานะ |
|---|---|---|
| **จากผลจริงสู่วิธีสอน** (§1 Strategy Analyzer) | กลยุทธ์ที่ได้ผลจริงกับเด็กจริง ได้น้ำหนักมากขึ้นทุกสัปดาห์ โดยมี kill switch | โค้ดเสร็จ รอเปิดสวิตช์ |
| **จากคำถามจริงสู่คลังความรู้** (§9) | คำถามที่ครูตอบไม่มั่นใจ → เป็นหน่วยงานที่เขียนความรู้ใหม่ทุกสัปดาห์ | รอ Learning Data |
| **Jev ช่วยชี้เมื่อกติกาเสมอกัน** (§5) | กรณีกำกวม ไม่ตัดสินด้วยลำดับโค้ด แต่ชั่งน้ำหนักอย่างมีเหตุผล | พร้อมเริ่ม |
| **เครื่องวัดที่ไม่หลับ** (scorecard ใน CI) | ทุก push ถูกวัด 5+1 ด่าน — ไม่มีวันไหนที่โมเดลแย่ลงโดยไม่มีใครรู้ | ✅ ทำแล้ววันนี้ |
| **Golden answers จากของจริง** (§6) | eval ไม่ใช่ของที่แต่งในห้อง — มาจากเด็กจริงทุกสัปดาห์ | รอ Learning Data |

## ระลอก 3: ขยายโดยไม่แตะของใคร (Scale Without Taking) — จำนวนเด็ก ×10

สิบล้านเท่ามาจาก "จำนวนเด็ก" มากกว่า "ความฉลาดต่อเด็ก" — และการขยายจำนวน
ต้องไม่สร้างความเสี่ยงกฎหมายใหม่:

| งาน | ทำไมสำคัญ |
|---|---|
| **KB ที่ถูกต้องตามกฎหมายตลอดไป** (docs/07 A+C+D) | ✅ **ปิดแล้ววันนี้** — เครื่องตรวจกฎหมาย + นโยบายสาธารณะ + playbook |
| **ค่าใช้จ่ายต่อเด็กที่ลดลง** (§8 Cost governor) | ครูที่แพงเกิน = สอนเด็กได้น้อย — คุมต้นทุนต่อ session คือขยายจำนวนเด็กโดยตรง |
| **KB สร้างเองได้เรื่อย ๆ** (expansion จากข้อมูลจริง) | ความรู้โตจาก (1) ทฤษฎีคำนวณได้ (2) ข้อเท็จจริงสาธารณะ (3) ประสบการณ์สอนจริง — ไม่เคยต้องแตะของใคร |
| **หลายภาษา/หลายวัฒนธรรม** | เด็กไทย จีน อังกฤษ — ครูคนเดียวกันแต่พูดภาษาเด็ก |

## ระลอก 4: หลักฐานว่าดีจริง (Prove It) — ความเชื่อมั่น ×10

| งาน | ผลลัพธ์ |
|---|---|
| **ตัวเลขก่อน-หลังต่อเด็ก** | พ่อแม่เห็น "ลูกอ่านโน้ตเร็วขึ้น 40% ใน 6 สัปดาห์" จากข้อมูลจริง ไม่ใช่คำโฆษณา |
| **ประสบการณ์ครูตัวจริง** | ครูเปียโนตัวจริงใช้ TIGA เป็นผู้ช่วย — รีวิว/คำติจากมืออาชีพ |
| **เวทีจริง** | เด็กที่ซ้อมกับ TIGA ขึ้นเวที/สอบผ่าน — หลักฐานที่ไม่มีใครโต้แย้ง |

## ส่วนที่ 3: ความจริงที่ต้องพูดตรง ๆ

- **สิบล้านเท่าไม่ใช่งานสัปดาห์เดียว** — แต่เป็น *ทิศทาง* ที่ทุกงานที่เลือกทำต่อจากนี้ต้องรองรับ
  ("งานนี้เพิ่มจำนวนเด็ก/คุณภาพต่อเด็ก/ความเร็วการเรียนรู้ ด้านไหน?" — ถ้าไม่มีคำตอบ งานนั้นไม่เข้าแผน)
- **คอขวดจริงตอนนี้คือการเปิดวาล์วข้อมูล** (SQL ที่อนุมัติแล้ว) — ระลอก 1-2 ทั้งหมดรอสิ่งเดียวกัน
- **ขอบเขตกฎหมายที่วาดไว้ (docs/07) คือเส้นตายของทุกระลอก** — ไม่มีไมล์สโตนไหนคุ้มที่จะข้าม
  เพราะแผนทั้งหมดตั้งอยู่บน "ขยายได้โดยไม่ต้องแบ่งปันเครดิตกับใครหรือจ่ายค่า license"

## ส่วนที่ 4: สรุปผู้บริหาร

**สูตรสิบล้านเท่า = (เด็กที่สอนได้ ×10) × (คุณภาพต่อเด็ก ×10) × (ความเร็วเรียนรู้ ×10)**
— ระลอก 1 ทำให้ครูเป็น "ครูส่วนตัว", ระลอก 2 ทำให้ครูเก่งขึ้นทุกวันโดยไม่ใช่แค่ตอนเราอัปเดต,
ระลอก 3 ทำให้ขยายได้ไม่จำกัดโดยไม่แตะของใคร (กฎหมายปลอด), ระลอก 4 ทำให้ทุกข้ออ้างมีตัวเลขจริง —
และขั้นต่อไปที่เปิดทุกอย่างคือปุ่ม Run ใน Supabase ของคุณ
