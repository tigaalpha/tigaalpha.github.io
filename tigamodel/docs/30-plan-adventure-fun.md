# 30 · แผนทำ Adventure Mode ให้ดีขึ้นและสนุกขึ้น (ร่าง → ปรับ 3 รอบ → รอเจ้าของช่วยปรับ)

เขียนจากโค้ดที่ส่งขึ้นจริงแล้ว (`adventure.tsx`, `quiz-quest.ts`) ไม่ได้เขียนจากความจำ
เนื้อเรื่องที่ต้องใช้: `29-adventure-story-canon.md` (ปี 2100 หาทรัพยากร เก็บพลังงานดาวฤกษ์/ดาวแก๊ส สู้ต่างดาว)

## 0. สภาพปัจจุบัน (วัดจากโค้ด)
- แมพเดียวยาวเส้นตรง 5,200 px ต่อดาว, มอนสเตอร์ 3 ชนิด (17 ตัวเรียงซ้ำ), มี 3 beacon คำถาม, บอสท้ายด่าน 1 ตัว
- ผู้เล่นมี 3 ปุ่ม: โจมตี (กดซ้ำ), กระโดด, สกิล (คูลดาวน์ 4.5 วิ) — ไม่มีการหลบ, ไม่มีคอมโบ
- ดรอป: ออร์บเลือด + คริสตัล ◆ แต่ **คริสตัลยังไม่มีที่ใช้** (นับเฉยๆ)
- ดาวที่เล่นได้: Luma, Ferro (Ferro คือ Luma สีใหม่ สถานะ ×1.7)
- สัตว์เลี้ยงยิงบอลช่วยแล้ว แต่ยังไม่มีเทสต์ที่มีสัตว์เลี้ยงจริง
- ยังไม่มีใครเล่นบนมือถือจริง (ความรู้สึกและความลื่นไม่ทราบ)

---
## รอบที่ 1 — ร่างแรก (ไอเดียทั้งหมด)
1. มอนสเตอร์ใหม่ต่อดาว (Ferro: หุ่นขุดสนิม, หนอนทราย; Kryo: ...), บอสทุกดาว
2. ดาวที่ 3–5 เล่นได้ (Kryo, Pyra, Nexa) + ด่านดาวแก๊สและด่านเก็บพลังงานดาวฤกษ์
3. คริสตัลใช้อัปเกรดอาวุธ/เกราะ, ไอเทมดรอปหายาก
4. ปุ่มหลบ (dash), คอมโบโจมตี 3 ท่า, สกิลที่สอง
5. แพลตฟอร์ม กับดัก ฉากเปลี่ยนระหว่างทาง
6. เควสต์รายวัน, ภารกิจเก็บทรัพยากรตามเนื้อเรื่อง
7. ออนไลน์: แผนที่ร่วมกับเพื่อน
8. เล่นเปียโนเป็นเวทย์ (กดคอร์ดเพื่อร่าย)

### คำวิจารณ์รอบที่ 1 (ทำไมร่างนี้ยังไม่ดีพอ)
- เป็นรายการของเยอะ ไม่ได้บอกว่าอะไรทำให้ "สนุก" — ความสนุกของเกมแนว side-scroller มาจากความรู้สึกต่อการกดหนึ่งครั้ง (ตีโดน, หลบทัน) มากกว่าจำนวนดาว
- ข้อ 2 และ 1 ใช้แรงมากสุดแต่ให้ความสนุกน้อยสุดถ้าการต่อสู้ยังจืด
- ข้อ 7 ต้องมีเซิร์ฟเวอร์/SQL ซึ่งต้องรอเจ้าของอนุมัติ — ไม่ควรอยู่ในรอบแรกๆ
- ข้อ 8 คือจุดขายเฉพาะของ TIGA (เกมนี้สอนเปียโน) แต่ร่างไม่ได้พูดถึงกติกาไมค์ (เสียงเกมห้ามรบกวนไมค์ ดู AGENTS.md)
- ไม่มีตัวชี้วัดว่าทำแล้วดีขึ้นจริง

---
## รอบที่ 2 — จัดลำดับตามผลต่อความสนุก ÷ แรงที่ใช้
**ชั้น A: ความรู้สึกต่อการกด (ทำก่อน ใช้โค้ดเดิมเป็นส่วนใหญ่)**
- A1 ปุ่มหลบ (dash + อมตะ 0.25 วิ, คูลดาวน์ 1.2 วิ) — ทำให้ท่าเตือนของบอสมีความหมาย
- A2 คอมโบ 3 ท่า (ท่า 3 แรงกว่าและผลักไกล) แทนการกดซ้ำท่าเดียว
- A3 มอนสเตอร์ต้องมีสัญญาณเตือนก่อนตี (ตอนนี้บอสมี มอนสเตอร์ธรรมดายังไม่มี)
- A4 เสียง/สั่น/hit-stop ตามระดับกราฟิก (มี hit-stop ใน High แล้ว ต้องเพิ่มเสียงตี ซึ่งต้องเป็นเสียง mic-safe ตามกติกา)
**ชั้น B: เหตุผลที่จะเล่นต่อ**
- B1 ใช้คริสตัลอัปเกรด 3 สาย (พลังโจมตี / เลือด / ความเร็วสกิล) — **คริสตัลหาได้จากการเล่นเท่านั้น ห้ามขาย ห้ามผูกกับการจ่ายเงิน** (กฎ AGENTS.md)
- B2 เควสต์รายวัน 3 ข้อ (เช่น เก็บ 15 ◆, ตอบถูก 5 ข้อ, ชนะบอสดาวใดก็ได้) จ่าย EXP ไม่ใช่เหรียญ
- B3 ระดับความยาก 3 ขั้น (Normal/Hard/Nightmare) ต่อดาว เพื่อให้เล่นซ้ำได้
**ชั้น C: เนื้อหา (ทำหลังชั้น A/B)**
- C1 มอนสเตอร์เฉพาะ Ferro 2 ชนิด + บอสท่าใหม่; C2 Kryo, Pyra, Nexa ทีละดาว ดาวละ 2 มอนสเตอร์ + บอส 1
- C3 ด่านพิเศษเนื้อเรื่อง: "เก็บพลังงานดาวแก๊ส" = เอาตัวรอดจากคลื่นมอนสเตอร์ 90 วินาที (ใช้เอนจินเดิม ไม่ต้องทำแมพใหม่)
**ชั้น D: จุดขายเปียโน**
- D1 ท่าไม้ตายร่ายด้วยการเล่นคอร์ดที่เพิ่งเรียน (ใช้ `quiz-quest.ts` ที่รู้ว่าผู้เล่นเรียนอะไรแล้ว) ผ่านเปียโนบนจอเท่านั้นก่อน
**ชั้น E: ต้องขออนุมัติ** ออนไลน์ร่วมกัน (SQL/เซิร์ฟเวอร์)

### คำวิจารณ์รอบที่ 2
- A1–A3 แตะลูปเกมกลาง ต้องมีวิธีทดสอบที่ไม่ใช่แค่ "ไม่ error" — ตอนนี้เทสต์ผ่านได้แม้เกมน่าเบื่อ
- B1 เสี่ยงเรื่องสมดุล: ถ้าอัปเกรดแรงเกินจะข้ามความท้าทาย ต้องมีเพดานและตารางตัวเลข
- D1 ถ้าให้ร่ายด้วยไมค์จะชนกติกาไมค์ → จำกัดเฉพาะแตะเปียโนบนจอ
- ยังไม่มีเกณฑ์ "เสร็จ" ต่อเฟส และยังไม่รู้ประสิทธิภาพมือถือจริง (ถ้าเกมกระตุกทุกอย่างข้างบนไม่มีความหมาย)

## รอบที่ 3 — แผนที่ใช้ทำงานได้ (เฟส, เกณฑ์เสร็จ, ความเสี่ยง)
### เฟส 3.0 — วัดก่อนแต่ง (ครึ่งวัน)
- เพิ่มตัวนับเบาๆ ใน `usage_events` (kind `adv`: เริ่ม/จบรอบ, ตายที่ x ไหน, ชนะบอส, คำตอบ beacon) เพื่อรู้ว่าคนเลิกเล่นตรงไหน — ใช้ตารางเดิม ไม่ต้องมี migration
- เกณฑ์เสร็จ: เห็นข้อมูลในแอดมิน funnel; เจ้าของลองเล่นมือถือจริงและบอกค่า fps/ความรู้สึก (เราตรวจเองไม่ได้)
### เฟส 3.1 — ความรู้สึกต่อการกด (A1–A4)
- เกณฑ์เสร็จ: เทสต์ใหม่ยืนยัน (1) dash ให้อมตะจริงในกรอบเวลา (2) ท่าคอมโบที่ 3 ดาเมจ ≥ 1.5× (3) มอนสเตอร์ธรรมดามีช่วงเตือน ≥ 0.25 วิ ก่อนทำดาเมจ; fps ใน Standard ไม่ลดลงเกิน 10% จากก่อนแก้
- ความเสี่ยง: ปุ่มบนมือถือเพิ่มเป็น 4 ปุ่ม อาจแน่น → ต้องเช็กจอ 320 px
### เฟส 3.2 — เหตุผลเล่นต่อ (B1–B3)
- ตารางอัปเกรด: 5 เลเวลต่อสาย, ราคา ◆ เพิ่มแบบเรขาคณิต, เพิ่มสถานะรวมสูงสุด +25% (เพดานคงที่)
- เควสต์รายวันจ่าย EXP ตาม `pvp-rpg.ts` เท่านั้น, ไม่จ่ายเหรียญ/เจม
- เกณฑ์เสร็จ: สคริปต์คำนวณว่าผู้เล่นที่เล่นดีตามปกติใช้เวลา ≥ 3 วันกว่าจะอัปเกรดสุดสายแรก
### เฟส 3.3 — เนื้อหา (C1–C3)
- ทำทีละดาว วัดด้วยเทสต์ปลดล็อกแบบเดียวกับ `smoke-adventure-boss.mjs`
- ลำดับ: Ferro จริง → ด่านเอาตัวรอดดาวแก๊ส → Kryo → Pyra → Nexa
### เฟส 3.4 — เปียโนเป็นเวทย์ (D1)
- ท่าไม้ตายต้องเลือก "คอร์ดที่เรียนแล้ว" (จาก `learnedTopics`) แล้วแตะบนเปียโนบนจอ; ถูก = แรงขึ้น, ผิด = สอนเหมือน QuizCard
- ห้ามใช้ไมค์ และเสียงใหม่ต้องเป็น noise หรือ blacklist ตามกฎ mic-safe
### เฟส 3.5 — ออนไลน์ (E) — **หยุดรอเจ้าของ** ต้องมีออกแบบตาราง + SQL ให้เจ้าของอนุมัติรายไฟล์

### ตัดทิ้ง/เลื่อน (ตั้งใจ)
- กราฟิก 3D แบบ ROV (เกินกำลังเว็บ 2D โค้ดวาด), ขายคริสตัล/ไอเทมด้วยเงินจริง (ห้าม)
### ความเสี่ยงรวม
1. ไม่เคยเล่นบนเครื่องจริง → เฟส 3.0 ต้องมาก่อน  2. สมดุลตัวเลข → ตารางและเพดาน  3. ปุ่มแน่นบนจอเล็ก  4. ขนาด chunk (ตอนนี้ ~28 kB → ตั้งเพดาน 60 kB)
### คำถามให้เจ้าของตัดสิน
- อยากให้ทำเฟสไหนก่อน (แนะนำ 3.0 → 3.1)?
- คริสตัลใช้อัปเกรดอย่างเดียวพอไหม หรืออยากให้แลกของตกแต่งหุ่นด้วย?
- ท่าเปียโนเป็นเวทย์: เอาตั้งแต่แรกหรือรอหลังเนื้อหา?
