# 33 · Adventure Online — เล่นร่วมกันหลายคน (แผนและสิ่งที่ทำแล้ว)

ที่มา: เจ้าของ 2026-10-11 — โหมดออนไลน์มัลติเพลเยอร์ หลายยูสเซอร์ต่อสู้กันเอง ร่วมกันสู้มอนสเตอร์ ช่วยกันทำภารกิจในเนื้อเรื่องเดิม (ออกนอกโลก ขุดแร่ เก็บทรัพยากรดาวแก๊ส/ดาวฤกษ์ รบกับเอเลี่ยน สงครามระหว่างดวงดาว สร้างไดสันสเฟียร์ ขยายอาณานิคม) มีหนังก่อนทุกฉาก และให้ปุ่มเข้าโหมดอยู่ตรงจุดที่เจ้าของวงสีแดงไว้ (เหนือปุ่ม Adventure ในล็อบบี้ PvP)

## เฟส O1 — ทำแล้ว (ไม่ต้องใช้ SQL / ไม่ต้อง deploy อะไร)
- ปุ่ม **Adventure Online** ในล็อบบี้ PvP (เหนือปุ่ม Adventure)
- ห้องโดยใช้ Supabase Realtime broadcast + presence (`adv-online.ts`, รูปแบบเดียวกับ `pvp-online.ts`): สร้างห้องได้รหัส 6 ตัว, เพื่อนกรอกรหัสเข้าห้อง, สูงสุด 4 คน
- เจ้าของห้องเลือกแผนที่ → ทุกคนเปิดแผนที่เดียวกัน (แต่ละคนดูหนังประกอบก่อนเริ่มด่านของตัวเองตามปกติ)
- ในด่าน: เห็นเพื่อนเป็นภาพเงาเรืองแสงพร้อมชื่อ/เลือด, ตีมอนสเตอร์ตัวเดียวกัน (ดาเมจที่ตีถูกส่งให้เพื่อนด้วยหมายเลขมอนสเตอร์ จึงตายพร้อมกัน; คนที่ปิดการฆ่าได้ของดรอป เพื่อนได้ EXP ครึ่งหนึ่ง), ตีบอสร่วมกัน, ฟีดแร่/แผงไดสันของเพื่อน, อีโมจิลอยเหนือหัว
- ไม่มีฝั่งเซิร์ฟเวอร์: ทุกเครื่องรันเกมของตัวเอง เชื่อกันเอง (ระดับความไว้ใจเดียวกับ duel ชวนเพื่อนเดิม)

## ข้อจำกัดที่รู้ (พูดตรงๆ)
- มอนสเตอร์ที่เกิดสุ่มระหว่างเวฟ (Jovia, Helios) ไม่มีหมายเลข จึงไม่แชร์การตาย — แชร์เฉพาะด่านที่มอนสเตอร์เกิดตำแหน่งตายตัว
- ตำแหน่งมอนสเตอร์ของแต่ละเครื่องไม่ตรงกันทุกพิกเซล (AI รันแยกกัน) — ใช้ "พลังชีวิต" ร่วมกันเท่านั้น
- ยังไม่ได้ทดสอบกับ Realtime จริง (คอนเทนเนอร์เข้า Supabase ไม่ได้): ทดสอบตรรกะห้อง/ข้อความด้วยตัวแทนในหน่วยความจำ (`scripts/smoke-adv-online.mjs`) และหน้า UI ด้วยเบราว์เซอร์ (`smoke-adventure-online.mjs`) ต้องลองสองเครื่องจริง
- ภารกิจที่เป็นของส่วนตัว (ขุดแร่-ส่งกลับโลก, ประกอบแผงไดสัน) ยังคิดผลที่เครื่องตัวเอง ยังไม่นับเป็น "ทีม"
- ด่านขับยาน (Void Gate) และการ์ดต่อไปแผนที่ยังเป็นเดี่ยว; ในห้องไม่ข้ามแมปอัตโนมัติ

## เฟสต่อไป (ให้เจ้าของเสริม)
1. **O2 ภารกิจทีม:** นับแร่/แผงไดสัน/สถานีรวมทั้งทีม — ทีมช่วยกันเติมโครงไดสัน (ใครขุดก็ได้ ใครประกอบก็ได้), ส่งพลังงานกลับโลกพร้อมกัน, อาณานิคมของทีมโตขึ้น
2. **O3 ต่อสู้กันเอง (PvP ในแผนที่):** โหมด "สงครามระหว่างดวงดาว" แบ่ง 2 ฝ่าย (Earth Fleet vs Rival Fleet), ยึดสถานีพลังงาน/ไดสันกันคนละฝั่ง, ใช้สกิลอาชีพที่เพิ่งทำ (130 สกิล) ต่อสู้กัน
3. **O4 ห้องสาธารณะ/จับคู่:** ตอนนี้ต้องแชร์รหัส — ถ้าอยากให้เจอผู้เล่นแปลกหน้าต้องมีที่เก็บห้อง (ตาราง Supabase + RPC = ต้องให้เจ้าของอนุมัติ SQL)
4. **O5 ความยุติธรรม/กันโกง:** ถ้าจะมีอันดับหรือรางวัลที่มีค่า ต้องให้เซิร์ฟเวอร์ตัดสิน (Edge Function = ต้องอนุมัติ deploy) ตอนนี้รางวัลยังเป็น EXP/คริสตัลในเครื่อง + เหรียญผ่านเพดานรายวันเดิมเท่านั้น
5. **O6 หนังเล่าเรื่องสงครามดวงดาว:** ฉากเปิดสงคราม, การประกาศตั้งไดสันสเฟียร์, อาณานิคมของทีมเติบโต (ใช้ระบบหนังเดิม)

## ต้องให้เจ้าของตัดสินใจ
- ต้องการให้ผู้เล่นแปลกหน้าเจอกันเองได้ไหม (ต้องมี SQL) หรือเล่นผ่านรหัสห้องกับเพื่อนพอ?
- PvP ในแผนที่ ให้ได้รางวัลอะไร (ยังเป็น EXP เท่านั้น? หรือเหรียญตามเพดาน?)
- ถ้าผู้เล่นเกิน 4 คน/ห้องต้องไหม (ตอนนี้ล็อก 4)


## เฟส O4 — เขียน SQL เตรียมไว้แล้ว (ยังไม่ได้รัน และแอปยังไม่เรียกใช้)
ไฟล์ `supabase-adv-public-rooms-migration.sql` (เพิ่มได้ รันซ้ำได้) สร้างตาราง `adv_public_rooms` + RPC 4 ตัว (`adv_room_open` / `adv_room_ping` / `adv_room_close` / `adv_rooms_list`) ให้เจ้าห้องประกาศห้องของตัวเอง และคนอื่นเห็นรายการห้องที่ยังว่างและยังเต้นอยู่ใน 90 วินาที
- ตารางเก็บแค่ "ป้ายประกาศ" (รหัสห้อง ชื่อเจ้าห้อง แมพ โหมดสงคราม จำนวนคน) เกมจริงยังวิ่งบนช่อง Realtime `advo:<CODE>` เดิม ไม่มีข้อมูลเกมหรือรางวัลผ่านตาราง
- ต้องล็อกอินเท่านั้น (ผู้เล่นแขกยังใช้รหัสห้องกับเพื่อน), หนึ่งเจ้าห้องมีได้หนึ่งห้อง, ห้องที่ไม่เต้นเกิน 10 นาทีถูกลบเอง
- **เจ้าของต้องอ่านแล้วอนุมัติก่อนรัน** ตามกฎ; หลังรันแล้วค่อยต่อ UI "ห้องสาธารณะ" ในล็อบบี้ (ยังไม่ได้ทำ เพราะถ้าเรียก RPC ก่อนรัน SQL จะพัง)
- O5 (เซิร์ฟเวอร์ตัดสินดาเมจ/อันดับ) ยังต้องเป็น Edge Function ที่เจ้าของอนุมัติ deploy
