> ยึดกับโค้ดจริง: `payment.tsx` (GEM_PACKAGES, BuyCurrencyModal),

## §1 วิเคราะห์: ทำไมเพชรยังไม่สร้างรายได้

**1. อุปสงค์แคบ** — ของที่ซื้อด้วยเพชรมีแค่ combat mythic ของหุ่น 50 ชิ้น
คนที่ไม่สน PvP (ส่วนใหญ่ของแอปเรียนเปียโน) จึงไม่มีเหตุผลจะเติมเพชรเลย

**2. จุดขายหลุดมือ** — moment of intent ที่แรงที่สุดคือ "เมื่อกี้อยากซื้อของ
แต่เพชรไม่พอ" — ปัจจุบันจบที่หน้า mascot หน้าเศร้า ไม่มีปุ่มต่อ

**3. ไม่มีของถูกขายเร็ว** — ราคา 4-25💎 ต่อชิ้นเหมาะกับคอลเลกชันนิสต์
แต่ไม่มีสินค้า consumable ราคา 1-5💎 ที่ใช้แล้วอยากได้อีก (สิ่งที่ทำให้
เกมมือถือทั่วโลกมีรายได้ต่อหัวสูงคือ consumable ไม่ใช่ cosmetic)

**4. วัดไม่ได้** — ไม่มี event ใด ๆ ใน modal เติมเงิน → ปรับราคา/แพ็ก/ปุ่ม
ทำได้แค่เดา

## §2 สถาปัตยกรรมเศรษฐกิจใหม่ (3 ชั้น)

```
ชั้น 1  SPARK CONSUMABLES (ของใช้หมด เพชร 1-9💎)
   สัตว์เลี้ยง: อาหารพรีเมียม/เซอร์ไพรส์กล่อง/ครีมบำรุง
   หุ่นยนต์: ชุดล้าง+ขัดเงา, สกินประกายชั่วคราว 7 วัน
   → ทำให้มี "เหตุผลจะเติมซ้ำ" ที่ราคาเข้าถึงง่าย (impulse buy)

ชั้น 2  PET GEM TIER (ของถาวรราคา 6-40💎 สำหรับสัตว์เลี้ยง)
   ลวดลายขน (skin), สร้อย/แหวน (accessory), ฉากหลังกรง (habitat)
   → ขยายตลาดเพชรจาก "คนเล่น PvP หุ่น" → "คนรักสัตว์เลี้ยงทุกคน"
   → ราคา+ความหายากเลียนแบบ GEM_WEAPONS ที่ผ่านมาแล้วทั้งระบบ

ชั้น 3  EXCLUSIVES (ของสะสมระดับบน 15-99💎)
   สายพันธุ์สัตว์เฉพาะเพชร (ยีราฟทอง, มังกรน้ำแข็ง ...), ชุดประกอบ
   → ทำกำไรสูงต่อรายการ, ตอบโจทย์ collector
```

**กติกาเหล็ก 3 ข้อ (ผูกกับ hard rules ของ repo):**
- เพชรทุกดวงที่ "ซื้อด้วยเงินจริง" ต้องผ่าน `submit_currency_purchase` +
  อนุมัติฝั่งแอดมิน (มี trigger กันปลอมเพชรอยู่แล้ว — ห้ามมีทางเขียน gems
  จาก client ใหม่เด็ดขาด)
- ของ consumable ต้องไม่กระทบผลเรียน (ไม่มี XP boost ที่ซื้อด้วยเพชร —
  จะทำให้ "เรียนดี = จ่ายเงิน" ซึ่งขัดกับแก่นแอปเรียนเปียโน; ให้ผลเฉพาะ
  ด้านสัตว์เลี้ยง/หุ่น/ความสวยงาม)
- ทุก event เติม/ใช้เพชรต้อง log ลง `usage_events` (kind="gem") ให้วัด
  funnel ได้ตั้งแต่วันแรก

## §4 รายละเอียดการทำงานที่สำคัญ (สำหรับ implement)

**ข้อ 1 — ปุ่มเติมใน buyWithGems:**
```
if (gems < item.gem) {
  แสดง GemShortPopup: ขาดอีก N💎
    [เติม 120💎 129฿ (แนะนำ)] [เติม 300💎 299฿] [เติม 50💎 59฿]
  กด → logUsage("gem","short:open:"+item.id) → setBuyCurrencyOpen(true)
       + seed แพ็กที่เลือกไว้ (pkgIdx) ให้กดยืนยันต่อได้เลย
}
```

**ข้อ 2 — event schema (เก็บใน usage_events, kind="gem"):**
| event | ยิงเมื่อ |
|---|---|
| `gem:open:<source>` | เปิด modal เติม (source = shop/pet/short-pvp ฯลฯ) |
| `gem:pkg:<n>` | เลือกแพ็ก 50/120/300 |
| `gem:submit:<n>` | กดส่งสลิป/สตริป |
| `gem:paid:<n>` | แอดมินอนุมัติ (RPC ฝั่ง server log) |
| `gem:spend:<item>` | ใช้เพชรซื้อสำเร็จ |

**ข้อ 3-4 — ของใหม่ทั้งหมดใน pet-lab.tsx:**
- `SPARK_FOODS` (premium foods ซื้อด้วยเพชร) — กินเข้า `PET_FOODS` flow เดิม
  ทั้งหมด (PET_MAX/decay/petHappy ไม่แตะ)
- `GEM_COATS` / `GEM_NECKLACES` / `GEM_HABITATS` — รูปแบบเดียวกับ
  `GEM_WEAPONS` (`gem: N, cost: 0`), เก็บใน localStorage กุญแจใหม่
  `tg_petgems` (แยกออกจาก owned หุ่นเพื่อไม่ให้ข้อมูลปนกัน)

**ข้อ 8 — Starter Pack:** ตาราง `profiles` **ไม่ต้องแตะ** — ใช้
`usage_events` เช็ค "เคยซื้อ starter pack หรือยัง" จาก event `gem:paid:starter`
(ถ้าเคย → ซ่อนแพ็ก) — ไม่มี SQL migration ใหม่เลยในสัปดาห์แรก

## §5 การวัดผล (KPI 30 วันหลัง launch ข้อ 1-4)

| KPI | ปัจจุบัน | เป้า 30 วัน |
|---|---|---|
| ผู้ใช้ที่เปิด modal เติม / สัปดาห์ | ไม่รู้ (ไม่มี log) | ≥ 8% ของ DAU |
| submit → อนุมัติ (paid conversion) | ไม่รู้ | ≥ 35% |
| ผู้ซื้อ consumable ซ้ำภายใน 14 วัน | 0 | ≥ 25% ของผู้ซื้อครั้งแรก |
| ARPPU (รายได้/ผู้จ่าย/เดือน) | ~0 | ≥ 150฿ |
| สัดส่วนสัตว์เลี้ยงที่มีของเพชร | 0% | ≥ 5% ของผู้เลี้ยงสัตว์ |

**Kill switch ป้องกันลบลบ:** ถ้า ARPPU < 60฿ ภายใน 30 วันหลัง launch ข้อ 1-4
→ หยุดเพิ่มของ consumable ใหม่ ทบทวนว่าปัญหาคือ "ไม่มีของอยากได้" หรือ
"ราคาผิด" ก่อนขยายต่อ

## §6 ปฏิทิน 4 สัปดาห์

| สัปดาห์ | ทำ | ผลลัพธ์ |
|---|---|---|
| **1** | ข้อ 1 + 2 (ปุ่มเติมในจุดขาด + funnel log ครบ) | เห็นตัวเลขจริงเป็นครั้งแรก + ปิดรั่วใหญ่ |
| **2** | ข้อ 3 + 4 (SPARK สัตว์เลี้ยง + gem cosmetic tier) | ตลาดใหม่เปิด มีของซื้อ 63 ชิ้น |
| **3** | ข้อ 5 + 6 + 8 (SPARK หุ่น + booster + starter pack) | consumable ครบสองฝั่ง + แพ็กแรกราคาต่ำ |
| **4** | ข้อ 7 + 9 + 10 (exclusives + exchange + weekly chest) | เศรษฐกิจครบวงจร พร้อมวัด ARPPU จริง |

**สิ่งที่แผนนี้ไม่ทำ (ป้องกันความเสี่ยง):**
- ไม่แตะ `profiles.gems` ด้วย client เด็ดขาด (ใช้ rail อนุมัติ + RPC เดิม)
- ไม่ทำ loot box แบบสุ่มซ่อนอัตรา (PDPA/จริยธรรม — กล่องสุ่มต้องโชว์
  อัตราได้ทุกชิ้น)
- ไม่ทำ pay-to-win ในการเรียน (ของเพชรไม่กระทบ XP หรือบทเรียน)
