## §1 สิ่งที่คงเดิมจาก v1 (ยังถูกต้อง)

- เป้าหมาย: เปลี่ยนเพชรจากเงินสะสมใช้ไม่จบ → ของที่อยากได้ตลอด
- 3 ชั้นเศรษฐกิจ: **SPARK consumable (1-9💎) → Pet cosmetic tier (4-25💎) → Exclusives (40-99💎)**
- กติกาเหล็ก: เพชรจากเงินจริงผ่าน rail อนุมัติเดิมทั้งหมด · ไม่แตะ `profiles.gems` จาก client · ไม่ขายผลการเรียน
- ปุ่มเติมในจุดเพชรไม่พอ (`buyWithGems`) + funnel logging ยังเป็นข้อ 1-2

## §4 รายละเอียดสำคัญที่ v2 เข้มขึ้น

**GemShortPopup (ข้อ 1):**
```
หัวป๊อป: "{ชื่อไอเทม} ต้องการเพชรอีก {N} 💎"
ปุ่มหลัก:  [💳 จ่ายด้วยบัตร — เข้าบัญชีทันที]   ← ตัวเลือกแรกเสมอ
ปุ่มรอง:   [🧾 สลิป PromptPay/Alipay/WeChat — รอแอดมินอนุมัติ]
ท้าย:      เพชรฟรีวันนี้เหลืออีก {8 - ใช้ไป} 💎 จากฝึก+ควิซ   ← N4: ทางฟรีต้องมองเห็น
event: gem:short:open:{item} · gem:short:card / gem:short:slip
```

**Fair-play check (ข้อ 5) — เขียนใน comment ของ SPARK_FOODS เอง:**
```
// FAIR PLAY (gem plan v2 §2): these foods restore only what free foods
// already restore — they never touch petBonusOf() and never add a stat a
// 30-coin chow cannot reach. What is sold is convenience, not combat power.
```

**Trigger ข้อ 3 (ร่างในไฟล์ SQL):** `after update on payments` เมื่อ
`status` เปลี่ยนเป็น `'approved'` และ `kind='currency'` → insert
`usage_events(user_id, kind='gem', item_id='paid:'||currency_amount)` —
additive, re-runnable (`create or replace function` + `drop trigger if exists`)

## §5 KPI (v2 — ปรับตามหลักฐาน N2/N4)

| KPI | ปัจจุบัน | เป้า 30 วัน | เป้า 90 วัน |
|---|---|---|---|
| เปิด modal เติม / สัปดาห์ / DAU | ไม่รู้ | ≥ 8% | ≥ 12% |
| submit → approved | ไม่รู้ | ≥ 35% | ≥ 45% |
| **median เวลา submit→approved** | ไม่รู้ | ≤ 6 ชม. | ≤ 2 ชม. |
| ผู้ซื้อซ้ำใน 14 วัน | 0 | ≥ 25% | ≥ 40% |
| ARPPU/เดือน | ~0 | ≥ 90฿ | ≥ 150฿ |
| สัดส่วนสัตว์เลี้ยงมีของเพชร | 0% | ≥ 5% | ≥ 15% |

**Kill switch:** ARPPU < 60฿ ที่ 30 วัน → หยุดเพิ่ม SKU ใหม่ · ถ้า "บัตร" คิดเป็น
<30% ของยอดหลังข้อ 7 → ปัญหาคือ latency อนุมัติ ให้ลงทุนกับการตรวจสลิกอัตโนมัติ (bank API) แทนการเพิ่มของ
