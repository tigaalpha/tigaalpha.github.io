## §1 Payer Lifecycle State Machine (ใหม่ — หัวใจ v4)

**หลักการ:** ไม่สร้างระบบใหม่ — `use-conversion.ts` มี state machine popup ครบ (id, kind, day,
`markConvSeen`, winback) ที่ทำงานกับ subscription trial อยู่แล้ว เพิ่ม "payer" เป็น state ขนานเข้าไปใน
เครื่องเดียวกัน ศูนย์ infra ใหม่

**State + สิ่งที่แอปทำ:**

| State | นิยาม (จาก event ฝั่ง server) | Action |
|---|---|---|
| `never` | ยังไม่เคยจ่าย | โชว์ First-Purchase ×2 (v3 มีอยู่) + Starter Pack 79฿ ครั้งเดียว |
| `first` | จ่ายครั้งแรก ≤7 วัน | "ขอบคุณ" + ของหลังการซื้อ (pet snack ฟรี) + soft-ask อีกชิ้นในตระกูลเดียวกัน |
| `repeat2+` | จ่าย ≥2 ครั้ง | เข้าสถานะ **นักสะสม** — ปลดล็อกชั้นร้าน "สะสมเท่านั้น" (สกินรุ่นจำกัด ไม่ใช่ stat) |
| `lapsing` | จ่ายแล้วแต่ 30 วันเงียบ และยังมาเรียน | popup สไตล์ winback เดิม: "แพ็กคืนฟอร์ม" ราคาพิเศษ 1 ครั้ง |
| `churned-payer` | จ่ายแล้ว + ไม่มาเรียน 30 วัน | ไม่ยิงโฆษณาขาย — รอ winback ของ subscription จัดการ (กัน spam) |

**กติกาเหล็ก:** state คำนวณจาก event ฝั่ง server (`gem:paid` ที่ trigger สร้าง — v3 แล้ว) ห้ามใช้
localStorage เด็ดขาด · popup ทุกชนิดใช้ `markConvSeen` เดิม = กัน spam ฟรี · state ไม่เข้า SQL ใหม่
(คำนวณ on-the-fly จาก `usage_events` + `currency_purchases` ที่มีอยู่)

## §2 Scarcity Calendar (ปฏิทินความขาดแคลน — deterministic ไม่ต้องแตะ DB)

**หลักการ:** Anchor SKU ของ v3 ยังใช้ "สัปดาห์นี้มีของแพงหนึ่งชิ้น" แบบมือถือ v4 เปลี่ยนเป็น
**เครื่องหมุนเวียนอัตโนมัติ**: เลือกของ featured จาก ISO week number + hash(id) — โค้ดล้วน
ไม่มี backend, ไม่มีคนต้องจัดรอบ, ร้านไม่มีวันซ้ำซาก

- **Featured 2 ช่อง/สัปดาห์:** 1 mythic gear หมุนเวียน + 1 pet cosmetic หมุนเวียน (เมื่อ §สัปดาห์ 2 แล้ว)

- **คอลเลกชันตามฤดูกาล** ดู §5

## §3 Kid-Safety & Compliance Gate (ใหม่ — **เงื่อนไขก่อนขยายร้าน**)

นี่คือเหตุผลที่แผนนี้**ต้อง**ทำก่อนข้ออื่นในสัปดาห์เดียวกัน: เรากำลังจะวางร้านของเพชรไว้หน้าเด็ก ทั้งที่
ยังไม่มีกลไกคุมการใช้จ่ายแม้แต่ตัวเดียว (ตรวจแล้ว: ไม่มี parentPin/spendCap ในโค้ดทั้ง repo)

**M1. โหมดผู้ปกครอง + รหัส 4 หลัก (localStorage + profile)**
- ตั้ง PIN ครั้งแรกเมื่อซื้อครั้งแรก (ไม่บังคับตั้งก่อน — กัน friction ตอนยังไม่มีเด็กจ่าย)
- การซื้อทุกครั้ง >99฿ ต้องใส่ PIN — เด็กกดเองไม่ได้เกินเพดาน

**M2. เพดานรายเดือน (default 500฿/เดือน แก้ได้ 100-2000฿)**
- นับจาก event `gem:paid` ฝั่ง server เป็นหลัก (client โชว์ประกอบ) — เกินเพดาน = ปุ่มซื้อ lock พร้อมข้อความ "ครบโควตาเดือนนี้ ผู้ปกครองปรับได้"
- ทำใน UI + เตือนที่ฝั่ง edge function ตรวจซ้ำก่อนสร้าง pending row (กัน bypass)

**M3. ประวัติการซื้อให้ผู้ปกครองเห็น** — แท็บ "การซื้อของลูก" ใน Profile (ใช้ตาราง `currency_purchases` ที่มีอยู่แล้ว ไม่แตะ schema)

**M4. ใบเสร็จ/ใบกำกับภาษี** — ปุ่มขอใบกำกับ (email) สำหรับซื้อสายบัตร (กฎหมายไทย: ผู้ซื้อขอได้)

**กติกาเหล็ก:** งาน M1-M3 เสร็จ**ก่อน**เปิดขาย consumable หมุนเวียน (§2) และ event shop (§5) —
ของวางขายได้ตลอด แต่เครื่องจักรกระตุ้นซื้อต้องมีเบรกก่อน

## §4 จิตวิทยาการตั้งราคา (ต่อยอด Anchor SKU ของ v3)

**4.1 Streak Shield (เพชร) — สินค้าที่ตลาดพิสูจน์แล้ว**
- `buyFreeze()` เดิม: 120 เหรียญ/ชิ้น ซื้อด้วยเหรียญได้เหมือนเดิม (**ห้ามถอดทางฟรี** — kill list v2)
- เพิ่มรุ่นเพชร: **Stack ×3 = 25💎** (ป้องกัน 3 วันติด) — ต่างจากของเหรียญตรงที่**กองได้หลายชิ้น**
- ตำแหน่ง: โชว์เฉพาะตอน streak ≥3 วันและยังไม่มี shield — ตอนกำลังกลัวพัง streak พอดี
- ไม่กระทบการเรียน/XP (kill list: ห้าม pay-to-win การเรียน) — ปกป้องแค่ตัวเลข streak

**4.2 Decoy pricing (แพ็กกลางออกแบบให้คุ้มสุด)**
- แพ็ก 59/129/299฿ เดิมปรับข้อเสนอ: 129฿ = 80💎 + โบนัสสัตว์ 1 ชิ้น (คุ้มสุด ตั้งใจให้เลือก), 299฿ = 200💎 + สถานะนักสะสม 30 วัน
- แสดงราคา/เพชร (฿/💎) — ให้ตัวเลขเปรียบเทียบทำงานแทนคำโฆษณา

**4.3 Bundle Builder "ห้องสะสม"** — เลือก cosmetic ใดก็ได้ 3 ชิ้น ลด 20% (เฉลี่ยต่อชิ้นต่ำกว่าเดี่ยว ผู้ซื้อหลายชิ้นได้เปรียบโดยไม่ลดราคาเดี่ยว)

**4.4 ประกันการซื้อครั้งแรก** — "ไม่พอใจ 7 วัน เพชรคืนเต็มจำนวน" (คืนฝั่ง server โดยแอดมิน — มี RPC อนุมัติอยู่แล้ว ใช้สวนทางกลับ) — ลด friction การลองครั้งแรก ซึ่งคือกำแพงสูงสุดตาม lifecycle §1

## §5 Event Economy (ใช้ `activeEventRef` ที่มีอยู่จริง)

ปฏิทิน 3 ภาษา/3 วัฒนธรรม (ตรงฐานผู้ใช้ ไทย-อังกฤษ-จีน):

| เดือน | อีเวนต์ | ของ exclusive (cosmetic เท่านั้น) |
|---|---|---|
| เม.ย. | สงกรานต์ | ชุดหุ่น "สายน้ำ" + สัตว์รดน้ำ (สกิน) 15-40💎 |
| ก.พ. | ตรุษจีน | กรงทอง + ชุดหุ่นมังกรทอง 20-60💎 |
| ธ.ค. | คริสต์มาส/ปีใหม่ | หมวกซานตาสัตว์ + หิมะในห้อง 10-35💎 |

- ขายเฉพาะช่วง 10-14 วัน (หน้าต่างจากวันที่ระบบ — deterministic เหมือน §2)
- **ของหมดอายุการขาย ไม่หายถาวร:** รอบหน้ากลับมาขายอีก (กัน FOMO ทารกณ์ — kill list ห้าม countdown ปลอม/กดดันเด็กเกิน) — แต่ปีหน้าราคา +25% (ราคาเก่าเป็นของ "ผู้ร่วมงานปีแรก")
- ทั้งหมดเข้าระบบเดิม (MYTHIC_GEAR/PetCosmetic array ในโค้ด + trigger เพชรเดิม) — ไม่มี SQL ใหม่

## §6 School Grants B2B2C (ตลาดใหม่ — ใช้ SchoolCheckoutModal ที่มีอยู่)

โรงเรียนซื้อคอร์สอยู่แล้ว (SchoolCheckoutModal) — เพิ่มสินค้า **"แพ็กเพชรห้องเรียน"**:

- ครูซื้อ 30×50💎 (ราคาพิเศษ) → ครูกระจายให้รายชื่อนักเรียนในห้อง
- นักเรียนได้เพชรเท่ากันทุกคน (บรรยากาศห้องเรียนไม่แบ่งรวยจน) — ครูเลือกได้ว่ากระจายทีละคนเป็นรางวัลหรือครบห้อง
- **ฝั่ง server:** RPC ใหม่ `school_grant_gems(school_id, student_ids[], gems_per_student)` — additive (`gems = gems + n`), เช็คว่า caller เป็นเจ้าของ school, มี cap ต่อสัปดาห์, log event ครบ — **ต้องเขียน SQL + ขออนุมัติ** (เหมือนกติกาเดิม)
- คุณค่า: AOV สูง (3,000-5,000฿/ใบสั่ง) + เพชรเข้าถึงเด็กทั้งห้อง = ตลาดกระตุ้น consumer ต่อเนื่องฟรี

## §7 Payer Cohort & LTV Dashboard (ต่อยอด AdminActivityDashboard)

- **Cohort grid:** แถว = เดือนซื้อครั้งแรก, คอลัมน์ = อายุ payer (M0-M6), ค่า = รายได้สะสม/คน (จาก `currency_purchases` approved)
- **การ์ดสุขภาพรายได้:** ARPPU, payer conversion %, repeat rate 30 วัน, refund rate, **อัตราอนุมัติสลิปอัตโนมัติ** (SlipOK ok/manual/fail แยกสี — ถ้า auto <70% ต้องตรวจเงื่อนไข)
- **Reconciliation รายสัปดาห์:** SlipOK ที่เสียค่าตรวจ vs สลิปที่อนุมัติจริง (กันค่าใช้จ่ายรั่ว)
- วาดด้วย pattern การ์ดเดิมของ dashboard ทั้งหมด — ไม่มี lib ใหม่

## §8 Platform Risk: PurchaseRail (กันวันที่ขึ้น Google Play)

สถานะจริง: APK แจกผ่าน GitHub Release (android-debug-latest) — **ไม่ผ่าน Play จึงใช้สลิป/บัตรได้ตามกฎ**
แต่ถ้าวันหนึ่งขึ้น Play (discovery ดีกว่ามาก) สินค้าดิจิทัลต้องใช้ Play Billing

**ทำตั้งแต่สัปดาห์ 1 ด้วยแรงงาน 1 ชม.:** ดึงจุดเรียกซื้อทั้งหมดเข้า interface เดียว
`startPurchase(pkg, rail)` โดย rail = `slip | card | (อนาคต) play` — UI/ราคา/funnel เหมือนเดิมทุกอย่าง
แค่สลับ rail ได้ เวลาขึ้น Play แค่เพิ่ม adapter ไม่ต้องแตะ 20 จุดขาย
